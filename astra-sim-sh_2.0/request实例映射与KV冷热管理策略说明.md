# SH-2.0 策略说明：请求实例映射与 KV 冷热管理

> 本文从体系结构、算法—软件映射与仿真三个视角，给出 SH-2.0 策略的通用说明。
> 全文与具体硬件配置、模型规格无关：拓扑规模、算力/带宽/容量、模型层数与维度等
> 均以参数符号表达，任何满足前提的晶圆级系统都可套用。

## 1. 策略定位

SH-2.0 是五版本演化链（WSC-LLM → FACE → SH-1.0 → SH-2.0 → SH-3.0）的第四站，
在 SH-1.0 的远端内存框架上做两项升级：

1. **KV 冷热管理从"整会话两态"细化为"模型层级的三态层次"**：第一次淘汰只把
   会话 KV 的**后一半层**外迁远端、前一半层留在片上；只有当所有可淘汰会话都已
   "半层化"仍不够时，才把整份外迁。由此形成"完整片上 → 前缀片上+后缀远端 →
   完整远端"的三级冷热梯度，**优先以较小的远端传输代价腾挪空间**；
2. **Prefill 负载指标从"块数"升级为"预计剩余服务时间"**：实例负载 = 在飞预填充
   剩余 + 排队预填充剩余 + 活跃解码剩余，三项都由 Roofline 解析式逐块/逐 token
   估计，使 Prefill 选点首次同时感知预填充与解码两类的真实时间压力。

此外，SH-2.0 的输入前缀口径为**折入 recompute**（2026-08-21 起）：会话首轮
（turn-0）把源前缀折入 prefill_length 全量重算，prefill 完成时入账本地 HBM；
后续轮历史 = 上轮最终上下文，由运行时 KV 账本动态维护（命中复用 / 跨实例迁移 /
远端恢复，被逐出则重算）。

P/D 两阶段独立选点的框架保持不变（Decode 仍按邻域 + 边际时延选择）。

## 2. 系统模型与记号

### 2.1 体系结构前提

- **晶圆级芯片**：R 行 × C 列二维 Mesh，N = R·C 个 NPU；
- **每 NPU**：峰值算力 F；本地 HBM 带宽 B_HBM、访问时延 λ_HBM、容量 C_HBM；
- **片间链路**：相邻 NPU 间带宽 B_NOC、逐跳时延 λ_NOC；
- **远端内存池**：边界 NPU 为边缘 NPU，各挂一个远端端口（带宽 B_rem、时延
  λ_rem），全体端口构成逻辑统一的 KV 池；B_rem ≪ B_NOC、B_HBM，是冷热分层的
  物理动因。

### 2.2 实例池与邻接图

m 个**互不重叠、铺满整片、等大的轴对齐矩形实例**（每实例 t 个 NPU，TP = t），
全部对等承担 P 与 D。实例邻接图边权初始为 1；Decode 候选的可调度距离上限沿用
FACE 准则 **D_limit = B_NOC / B_HBM**。

### 2.3 模型与 KV 容量记号

设模型 L 层、隐藏维 d、注意力头数 H、元素字节 b：

- 每 token 全模型 KV 字节数 B_KV = 2·L·d·b；长度 h 上下文对应 B_KV(h) =
  2·L·h·d·b；**任意层区间 [l₀, l₁) 的 KV 与层数成正比**（B_KV 只依赖层区间
  长度），这是半层划分的字节基础；
- 注意力头按**整头**划分到 t 个 NPU（不整除时前若干 NPU 各多一头），分片逐 NPU
  不等——**容量检查逐 NPU 进行**；
- 逐 NPU 账本：剩余 = C_HBM − 权重分片 − 驻留分片（区分层区间）− 预留分片；
- **KV 保留水位**（参数 R_kv）：逐 NPU 为"R_kv token 完整 KV"保留空闲。

### 2.4 负载记号

会话多轮，首轮绝对时刻到达、后续轮"上轮完成 + 思考间隔"到达。输入口径为折入
recompute（2026-08-21 起）：首轮请求的源前缀已折入其 prefill_length（全量重算），
不再单独声明输入前缀：

- **可复用历史** h_hist = 上轮最终上下文（驻留与否/位置由运行时 KV 账本动态维护）；
- **待预填充量** = 本轮 prefill_length（首轮已含源前缀全量）；
- h_pre = h_hist + 本轮 prefill_length；h_fin = h_pre + 生成长度；
- 预填充按 p_chunk 分块。

## 3. 请求实例映射策略

### 3.1 Prefill 阶段选择（到达时）

**第一步：逐 NPU HBM 可行性过滤。** 对每个实例 i、每个 NPU q：

> required = h_fin 的完整 KV 分片 − 会话已驻留本实例的分片（按当前驻留状态折算）
> reclaimable = 净剩余 + 可淘汰冷会话的驻留分片
> **可行 ⇔ ∀q：reclaimable ≥ required**

驻留实例只要求增量字节，其他实例要求全量最终 KV——纯容量口径，**不因会话的
驻留位置偏爱任何实例**（部分驻留会话同样参与全实例负载均衡）。

**第二步：服务时间负载排序。** 对每个可行实例取负载快照：

> **L_i(t) = L_run_i + L_queue_i + L_decode_i**
>
> - L_run：该实例**在飞预填充请求**的剩余时间——按剩余块逐块用 Roofline 估计
>   求和（在线无块级进度事件时取全量上界近似）；
> - L_queue：排队预填充请求（不含在飞者，避免双计）逐块估计求和；
> - L_decode：每个活跃解码请求的剩余时间——**期望剩余 token = 平均生成长度 −
>   已生成**，从当前上下文起逐 token 估计求和；平均生成长度取自负载级统计
>   （在线为冻结常数），**不使用单请求的真实剩余长度**（不做预知）。

排序键：**（L_i， 最近承接时刻（无者视为最早）， 实例编号）** 字典序最小。

**逐块估计的正确性**：预填充注意力代价随"块长 × 可见上下文"二次增长，把多个
块聚合为一个大块估计会**系统性高估**（二次性所致），因此负载必须**逐块求和**。

### 3.2 Decode 阶段选择（Prefill 完成边界）

沿用 FACE 算法：

1. 候选 = 与 Prefill 实例加权距离 ≤ B_NOC/B_HBM 的实例；
2. 对每个候选，预测模型给出"批加入本请求前后"的混合迭代时长差，除以实例规模得
   **单位 NPU 边际代价**；
3. 可行候选中取边际代价最小；**平局破除在 FACE 基础上加一级**：
   > （单位 NPU 边际代价， −剩余 HBM 容量， 实例编号）
   即边际代价精确相同时，**剩余 HBM 容量更大者优先**，再平局取编号最小。容量
   仍是破平项而非主目标，保持"代价优先"的 FACE 语义。

### 3.3 迭代组织

混合迭代同 FACE/SH-1.0：一次迭代 = 队首 1 个 p_chunk 块 + 全部活跃解码各
1 token；预填充 FCFS；解码连续批处理。部分驻留会话的首个预填充块被拆为"前缀层
段"与"后缀层段"两段发射，后缀段以后缀恢复的逐 NPU 完成门为依赖（见 4.4）。

## 4. KV 冷热管理策略（核心：三级层次）

### 4.1 三态模型

| 状态 | 含义 | 片上层数 |
| --- | --- | --- |
| 完整片上（LOCAL） | 全部 L 层在本实例 HBM | L |
| 部分驻留（PARTIAL） | **前 ⌈L/2⌉ 层片上 + 后 ⌊L/2⌋ 层远端** | ⌈L/2⌉ |
| 完整远端（REMOTE） | 全部层在远端池，片上无分片 | 0 |

**层划分规则**：第一次淘汰只外迁**后 ⌊L/2⌋ 层**（按实际模型层数计算，奇数层
模型保留较大半）；由于 KV 字节与层数成正比，半层外迁恰好释放一半空间、传输一半
字节。层区间分片逐 NPU 按整头规则计算，与全量分片严格守恒。

### 4.2 类型化两阶段 FIFO 逐出

逐出按**触发请求的会话类型**分两类（如"人类轮次"与"工具调用轮次"，由负载声明的
下一轮触发类型标记；无声明者归人类类），**固定先逐人类类、再逐工具类**；每类
内部两阶段，**每次逐出后立即重查水位**：

- **阶段 1（半层化）**：反复选取该类中"最早完成的完整片上非活跃会话"，仅把其
  后半层外迁远端（状态 → PARTIAL，释放一半字节）；
- **阶段 2（整体外迁）**：仅当该类所有可淘汰会话都已半层化且容量仍不足，才把
  仍留在片上的前缀整体外迁（状态 → REMOTE，释放全部字节）。

- **类内 FIFO 顺序**：（最后完成时刻， 会话标识）升序，平局按会话标识字典序；
- **候选资格**：本实例上"已完成且非活跃"的会话；触发请求自身被保护；
- **逐 NPU 收敛**：逐出直到实例内每个 NPU 同时满足需求；全类全阶段耗尽仍不足
  则报错；
- **触发时机**：准入、历史准备、Decode 预约/交接/增长、预填充增长、完成后水位
  恢复（逐 NPU 检查剩余 ≥ R_kv 分片，同样类型化两阶段）。

设计意图：**先用"半层外迁"这种代价减半的动作腾挪**，把"整份外迁"留作兜底；
类型化顺序则保护与当前请求同类型的会话（如工具轮触发时优先动人类轮的冷数据，
降低自己下一轮被逐的概率）。

### 4.3 命中复用路径（新请求选定 Prefill 实例后）

1. **新会话**：建立片上记录（0 层起步，随预填充增长）；
2. **完整片上 + 同实例**：零开销复用；
3. **完整片上 + 异实例**：整份（全 L 层）NoC 迁移，逐相对 TP 编号配对、确定性
   维度序路由（完整驻留态因此只有弱亲和）；
4. **部分驻留**：同实例命中时只恢复远端后缀；跨实例落点时前缀先经 NoC 迁至
   新实例、后缀再从远端读回（见 4.4）；
5. **完整远端**：任一可行实例全量读回（最近边缘端口 + 维度序路由）。

### 4.4 部分驻留的恢复路径与流水化

部分驻留会话与其他会话一样按负载均衡选点，恢复路径按落点分两种：

- **同实例命中**：前缀零迁移，只从远端读回后缀层段，合并为完整片上；
- **跨实例落点**：先在目标实例为前缀腾出容量，把**前缀层段 [0, 驻留层数) 经
  NoC 逐相对 TP 编号迁移**到新实例（确定性维度序路由），会话的物理归属随即改随
  新实例；随后在新实例从远端读回**后缀层段**。两段合计恰好搬完整份历史——
  前一半走片上网络、后一半走远端端口。

- **流水化恢复**：后缀恢复与前缀计算**段内并行**——首个预填充块拆为"前缀层段"
  （依赖就绪即算）与"后缀层段"（依赖远端后缀逐 NPU 写入完成的门），恢复流量与
  计算在时间上重叠；跨实例时前缀迁移置于恢复链之前，迁移完成后同样进入该流水；
- **退化归一**：若截断后可复用历史为 0 且会话处于部分驻留态，直接归一化为完整
  片上空会话（无后缀可恢复，避免零字节读回）。

### 4.5 P→D 交接

- Prefill 完成后 Decode 独立选点；异实例则整份（全层）NoC 交接后进入解码增长；
- 解码阶段 KV 单调增长至 h_fin（不收缩）。
- 注：源声明前缀的"到达时截断"通道已于 2026-08-21 随 sidecar 机制移除；
  recompute 单口径下 turn≥1 历史恒等于上轮最终上下文，不存在截断路径。

## 5. 算法—体系结构映射分析

1. **半层划分 ↔ 远端带宽的折中**：远端读写是全系统最慢的路径（B_rem 最小）。
   两阶段逐出让"腾空间"的第一次代价减半——只搬后半层、留前半层；由于注意力
   计算需要全部层，任何使用都需恢复后缀，因此半层态是**纯空间腾挪态**，不是
   可直接服务态。这一设计把"容量压力"与"恢复延迟"解耦为两个独立旋钮。
2. **前缀分层恢复 ↔ 注意力的层序性**：Transformer 层严格顺序执行，前层 KV 是
   后层的必要输入。把会话拆为"片上前缀 + 远端后缀"后，同实例命中只需拉回后缀
   （一半字节走最慢的远端路径）；跨实例落点时前缀走片上网络、后缀走远端端口，
   两段准备完成后即可续算。半层态因此成为**空间腾挪与恢复代价之间的折中结构**，
   而非对实例归属的锁死。
3. **服务时间负载 ↔ 计算-访存双界估计**：L_i(t) 的三项都用"max(计算界, 访存界)"
   的 Roofline 结构估计，逐块/逐 token 求和以尊重注意力的二次性；解码剩余用
   负载级平均而非单请求真值，保证**不依赖预知**（在线可实现性原则）。这使
   Prefill 选点从"块数均衡"进化为"端到端时间均衡"，能看见长上下文解码对实例
   的持续占用。
4. **类型化逐出 ↔ 会话时间局部性**：多轮负载中，同一会话的下一轮类型可知
   （人类/工具）。按触发类型排序牺牲对象，是对"谁更可能很快回来"的启发式
   保护——被逐出者的恢复代价（远端读回）直接进入下一轮时延。
5. **核心局限**：完整片上会话仍随独立选点跨实例整份迁移；部分驻留会话跨实例时
   也要付出"前缀 NoC 迁移 + 后缀远端读回"的整份历史搬运代价——**选点目标不含
   KV 位置与迁移/恢复成本**，负载均衡可能恰好把请求派往恢复代价最高的落点；
   Decode 选点同样不含 KV 位置；实例图边权不随迁移流量更新，"加权距离"实际退化
   为静态跳数。这些由 SH-3.0 的"一次映射 + 会话亲和"收口。

## 6. 仿真视角

- **双层架构**：Python 策略进程 + C++ 离散事件引擎在线闭环；决策边界为到达 /
  预填充完成 / 解码完成 / 请求完成；同批内先完成类后到达类；负载估计用的
  平均生成长度等统计量在物化期**冻结为常数**，在线不做增量统计（保证决策只依赖
  冻结输入与已发生事实）。
- **三段式计算图**：到达段 = 历史逐出 → 历史迁移/读回（部分驻留同实例为后缀
  恢复，跨实例为前缀 NoC 迁移 + 后缀远端恢复两段，均与前缀计算流水重叠）→
  就绪屏障 → 预填充整段（逐块聚合）；解码段 = Decode 逐出 →
  P→D 交接 → 解码整段（逐 token span）；完成段 = 完成逐出 → 下一轮到达闹钟。
- **物理模型**：Roofline + 逐 NPU HBM 流体均分模型（恢复 DMA、通信读写、池
  读写与计算共享同一带宽池，并发 N 路均分 B_HBM）；远端端口单事务 FIFO
  （λ_rem + 字节/B_rem）；拥塞感知网络 + 维度序路由；节点带本地 HBM 计费模式
  标记（读/写/纯过路），确保每字节在正确的端点计费一次。
- **可观测指标**：三级状态的转移流（半层化/整体外迁/后缀恢复/全量恢复的次数与
  字节）、逐会话 KV 层级快照、逐 NPU 分层账本（权重/驻留/预留 + 层区间）、
  HBM 共享时段与并发作业数、重算口径（复用后剩余预填充 token）、截断丢弃量、
  逐请求时延与吞吐、决策与图的摘要校验值。

## 7. 策略小结

| 维度 | 做法 |
| --- | --- |
| P/D 组织 | 共享实例池，逻辑解耦，两阶段独立选点（承 SH-1.0） |
| Prefill 选择 | 逐 NPU 可行性过滤 →（服务时间负载 L_i， 最近承接时刻， 编号） |
| 负载指标 | L_run + L_queue + L_decode，Roofline 逐块/逐 token 估计，解码用平均生成长度 |
| Decode 选择 | 邻域内单位 NPU 边际时延最小；平局依次比剩余 HBM 容量、编号 |
| KV 层次 | 完整片上 / 前缀片上+后缀远端 / 完整远端，三级 |
| 层划分 | 前 ⌈L/2⌉ 层驻留，后 ⌊L/2⌋ 层首迁（字节对半） |
| 淘汰 | 类型化（先人类类后工具类）两阶段 FIFO：（完成时刻， 会话标识），逐 NPU 收敛 |
| 部分驻留恢复 | 负载均衡选点：同实例只拉后缀；跨实例前缀 NoC 迁移 + 后缀远端恢复 |
| 前缀语义 | 折入 recompute：turn-0 前缀折入 prefill 全量重算；turn≥1 历史 = 上轮 final，账本裁定复用/迁移/恢复/重算 |
| 容量不足 | 挂起等待，逐决策点重查，不改映射 |

一句话概括：**把冷热边界从"整份会话"下沉到"模型层"——半层外迁优先、整体外迁
兜底；选点一律负载均衡，部分驻留会话跨实例时前缀走片上网络、后缀走远端恢复；
Prefill 负载从块数升级为 Roofline 服务时间，首次同时看见预填充与解码的时间压力。**
