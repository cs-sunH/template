# SH-1.0 策略说明：请求实例映射与 KV 冷热管理

> 本文从体系结构、算法—软件映射与仿真三个视角，给出 SH-1.0 策略的通用说明。
> 全文与具体硬件配置、模型规格无关：拓扑规模、算力/带宽/容量、模型层数与维度等
> 均以参数符号表达，任何满足前提的晶圆级系统都可套用。

## 1. 策略定位

SH-1.0 是五版本演化链（WSC-LLM → FACE → SH-1.0 → SH-2.0 → SH-3.0）的第三站，
在 FACE 的"共享实例池 + 两阶段独立选点"框架上引入**远端内存层**，把会话 KV 的
命运从"删除后重算"改为"**完整缓存的逐入逐出**"：

- 请求映射框架沿用 FACE：Prefill 按工作量均衡选点、Decode 按邻域 + 边际时延独立
  选点，但 Prefill 选择新增**逐 NPU 的 HBM 可行性过滤**；
- KV 管理从两态（片上/删除）升级为两态（**片上/远端**）：淘汰不再丢弃历史，而是
  把整份会话 KV 写入挂在**边缘 NPU** 上的统一远端内存池；下次命中再从最近的
  边缘端口读回。

由此，SH-1.0 **以远端传输换取"零重算"**，但历史 KV 的驻留位置仍只是被动的恢复
对象——它不构成 Prefill 选点的亲和性约束（仅通过容量可行性间接起作用）。

## 2. 系统模型与记号

### 2.1 体系结构前提

- **晶圆级芯片**：R 行 × C 列二维 Mesh，N = R·C 个 NPU；
- **每 NPU**：峰值算力 F；本地 HBM 带宽 B_HBM、访问时延 λ_HBM、容量 C_HBM；
- **片间链路**：相邻 NPU 间带宽 B_NOC、逐跳时延 λ_NOC；
- **远端内存池（本策略启用）**：网格**边界上的 NPU 为边缘 NPU**，每个边缘 NPU
  挂一个远端内存端口，带宽 B_rem、时延 λ_rem；全体端口在逻辑上构成**统一地址
  空间**的 KV 池（写入与读回可使用不同端口）。边缘端口带宽通常显著低于片上
  HBM 与 NoC 链路（B_rem ≪ B_NOC），这是冷热分层的物理动因。

### 2.2 实例池与邻接图

芯片划分为 m 个**互不重叠、铺满整片、等大的轴对齐矩形实例**（每实例 t 个 NPU，
TP = t），全部实例对等承担 Prefill 与 Decode。实例邻接图边权为 1，加权距离取
最短路；Decode 候选的**可调度距离上限**沿用 FACE 准则：

> D_limit = B_NOC / B_HBM

### 2.3 模型与 KV 容量记号

设模型 L 层、隐藏维 d、注意力头数 H、元素字节 b：

- 每 token KV 字节数 B_KV = 2·L·d·b；长度 h 上下文对应 B_KV(h) = 2·L·h·d·b；
- 注意力头按**整头**划分到 t 个 NPU（不整除时前若干 NPU 各多一头），分片逐 NPU
  不等——**容量检查逐 NPU 进行**；
- 逐 NPU 账本：剩余 = C_HBM − 权重分片 − 驻留 KV 分片 − 已承诺预留分片；
- **KV 保留水位**（参数 R_kv）：每实例逐 NPU 为"R_kv token 完整 KV"保留空闲。

### 2.4 负载记号

会话多轮：首轮绝对时刻到达，后续轮在"上轮完成 + 思考间隔"后到达。派生量
h_hist、h_pre、h_fin 同前；预填充按 p_chunk 分块。

## 3. 请求实例映射策略

### 3.1 Prefill 阶段选择（到达时，两步）

**第一步：逐 NPU HBM 可行性过滤。** 对每个实例 i、每个 NPU q：

> required_(i,q) = h_fin 对应的 KV 分片 − 会话已驻留在本实例的分片
> reclaimable_(i,q) = 剩余空间 − 其他在飞请求的预留增量 + 可淘汰冷会话的分片
> **可行 ⇔ ∀q：reclaimable_(i,q) ≥ required_(i,q)**

即"净剩余 + 可回收"必须**逐 NPU 同时**覆盖最终上下文的全量或增量。这是 SH 系列
相对 FACE 的第一处增强：容量从"守门员"升级为**准入过滤器**——不可行的实例根本
不参与排序。

- 若当前无任何实例可行但"腾空后可行"（分片 ≤ C_HBM − 权重），请求**挂起等待**，
  在每个后续决策点重查（保持先来先服务序）；
- 若腾空也放不下（请求本身超过单实例容量），判定为配置错误，立即报错终止。

**第二步：工作量均衡排序。** 在可行实例中取字典序最小：

> **（队列全部请求的剩余预填充块数之和， 最近承接时刻（无者视为最早）， 实例编号）**

### 3.2 Decode 阶段选择（Prefill 完成边界）

沿用 FACE 算法，不含任何 KV 位置项：

1. **邻域过滤**：候选 = 与 Prefill 实例加权距离 ≤ B_NOC/B_HBM 的实例；
2. **增量代价**：对每个候选，用预测模型比较"批加入本请求前后"的混合迭代时长，
   差值除以实例规模得单位 NPU 代价；
3. **选择**：可行候选中单位 NPU 代价最小；精确平局按实例编号升序轮转。

Decode 的 HBM 检查仍是"排除不可行者"，不改变代价排序；**Decode 归属不因 KV
驻留位置或迁移代价重选**。

### 3.3 迭代组织

与 FACE 相同的混合迭代：实例空闲且有待做工作时，一次迭代 = 队首请求的 1 个
p_chunk 块 + 全部活跃解码请求各 1 token；预填充 FCFS；解码连续批处理，完成即
触发同会话下一轮计时。

## 4. KV 冷热管理策略（核心）

### 4.1 两态模型（片上 ↔ 远端）

| 状态 | 含义 |
| --- | --- |
| 完整片上（LOCAL） | 整份会话 KV 驻留于某一实例的本地 HBM |
| 完整远端（REMOTE） | 整份会话 KV 存于远端内存池，片上无分片 |

**逐出单位永远是整份会话**（全部 L 层、全部 NPU 分片同进同出），没有按层切分的
中间态（那是 SH-2.0 的内容）。会话同一时刻只有一个权威位置。

### 4.2 历史复用三路径（新请求选定 Prefill 实例后）

1. **本地命中**：KV 已在选定实例——零通信复用；
2. **跨片迁移**：KV 在其他实例片上——逐相对 TP 编号一一配对，经 NoC 发送
   （目标先落位、源端收到确认后释放），确定性维度序（如 XY）最短路由；
3. **远端读回**：KV 在远端——对每个目标 NPU 分片：
   - 选择**最近边缘 NPU**：到目标 NPU 的曼哈顿跳数最小者，等距取编号最小；
   - 由控制核向该边缘发 1 字节请求；边缘从远端池读出该分片（端口事务 =
     λ_rem + 字节/B_rem）；
   - 分片经 NoC 以确定性维度序路由送达目标 NPU 落位；
   - 全部分片读回且实例级就绪门通过后，才开始本轮推理。

新会话首轮则直接建立片上记录，无传输。

### 4.3 淘汰写远端路径

淘汰某会话时，对每个源 NPU 分片：

- 选**最近边缘 NPU**（同上规则）；
- 源 ≠ 边缘：源经 NoC 发送至边缘（源端计一次本地读），边缘向远端池写入
  （端口事务 = λ_rem + 字节/B_rem），完成后 1 字节确认回源；
- 源 = 边缘：直接同侧写入，仅计一次本地读；
- **源端 HBM 空间在收到写回确认之后才释放**（账面状态即时更新，物理释放以
  确认为准）。

### 4.4 FIFO 逐出规则

触发时机（四类）：请求准入、历史准备的目标容量、Decode 预约/交接/增长、完成后的
水位恢复。

- **候选**：本实例上"已完成且非活跃"的片上会话；触发请求自身被保护；
- **淘汰顺序**：按 **（最后完成时刻， 会话标识）** 升序——最早完成的整份先走，
  平局按会话标识字典序；
- **逐 NPU 收敛**：每次淘汰后立即重查，直到实例内**每个 NPU** 同时满足需求；
  候选耗尽仍不足则报错（配置层面不可解）；
- **水位恢复**：每次请求完成后，逐 NPU 检查"剩余 ≥ R_kv 水位分片"，同样按 FIFO
  逐出直到满足或无候选（无候选时记录未满足项，不无限循环）。

### 4.5 会话亲和性与 P→D 交接

- 完整片上会话**弱亲和**：因 Prefill/Decode 独立选点，会话 KV 可能随轮次跨实例
  迁移（每次整份 NoC 搬运）；
- **P→D 交接**：两阶段落在不同实例时，整份 KV 按 h_pre 计字节逐相对编号交接；
  同实例零开销；
- 会话完成后的权威位置 = Decode 实例，成为下一轮命中的判断基准。

### 4.6 上下文截断

到达时若声明的可复用前缀小于会话现存上下文（上下文窗口截断），先按差额回收/
核销片上或远端的账面，再进行后续准入；活跃会话禁止截断。

## 5. 算法—体系结构映射分析

1. **边缘 NPU ↔ 远端内存的物理入口**：晶圆的物理边界天然提供一批"离片外存最近"
   的接入点。SH-1.0 把远端池挂在全部边界 NPU 上，并让每次读写都走**最近边缘**
   ——把"到远端的距离"从全局问题降为局部选择问题，NoC 段代价被曼哈顿最短距离
   约束在一个小邻域内。
2. **端口 FIFO ↔ 远端带宽的守恒**：每个边缘端口一次只服务一个事务，其余排队。
   传输时间 = λ_rem + 字节/B_rem，线性、可预测。整份会话 KV（可能达数百 GiB）
   在单口上串行耗时极长——这**正是冷热分层的量化依据**：只有冷数据才付得起这个
   代价，热数据必须留在片上。
3. **逐 NPU 准入过滤 ↔ 不均匀分片的正确性**：整头划分使各 NPU 的 KV 分片不等，
   容量可行性必须逐 NPU 判定。"净剩余 + 可回收 ≥ 需求"的公式把在飞请求的预留、
   冷会话的可回收量全部纳入，避免超卖。
4. **保留的水位设计**：R_kv 水位保证任何实例在稳态下都有接纳一个大上下文会话的
   余量，使"逐出-恢复"循环有缓冲空间，避免频繁的抖动性逐出。
5. **核心局限**：历史驻留位置与迁移/读回代价**不进入选点目标**——下一轮请求仍
   可能被派往没有其 KV 的实例（触发整份 NoC 迁移或全量远端读回）；P→D 独立
   选点照旧带来整份交接。这构成 SH-2.0（分层冷热 + 负载升级）与 SH-3.0（会话
   亲和一次映射）的改进起点。

## 6. 仿真视角

- **双层架构**：Python 策略进程 + C++ 离散事件引擎，经文件桥协议在线闭环；
  决策边界为到达 / 预填充完成 / 解码完成 / 请求完成。同一决策批内：先处理完成类
  （其中先预填充完成、后解码完成），再处理到达类，最后统一准入与发射——保持
  确定性事件序。
- **三段式计算图发射**：到达边界发射"历史逐出 → 历史迁移/读回 → TP 就绪屏障 →
  预填充整段（按 p_chunk 分块聚合）"；预填充完成边界发射"Decode 逐出 → P→D
  迁移 → 解码整段"；请求完成边界发射"完成逐出 → 下一轮到达闹钟"。KV 传输节点
  与计算节点以依赖边编排在同一张图中，物理时序由引擎裁决。
- **远端内存物理模型**：逐端口单事务 FIFO，事务时长 λ_rem + 字节/B_rem；读写
  在数据端点 NPU 的本地 HBM 计一次费，纯过路的中间 NPU 不计费。
- **本地 HBM 争用模型**：逐 NPU 流体模型——并发字节流均分 B_HBM，每个作业先付
  λ_HBM 纯时延；计算作业的算子按峰值算力并行排空，保持"计算界 vs 访存界取大"
  的 Roofline 语义。
- **网络模型**：拥塞感知解析网络，链路 B_NOC、逐跳 λ_NOC，KV 迁移与 1 字节
  控制消息均走确定性维度序路由。
- **可观测指标**：逐会话的 KV 动作流（本地命中 / NoC 迁移字节 / 远端写入字节 /
  远端读回字节 / 逐出原因与时点、每分片的路径与跳数）、逐 NPU HBM 水位与权重/
  驻留/预留账本、边缘端口的在飞与峰值队列统计、重算工作量口径（复用后剩余的
  预填充 token 数）、逐请求时延与吞吐、决策摘要校验值。

## 7. 策略小结

| 维度 | 做法 |
| --- | --- |
| P/D 组织 | 共享实例池，逻辑解耦，两阶段独立选点（同 FACE） |
| Prefill 选择 | 先逐 NPU HBM 可行性过滤，再按（剩余块数， 最近承接时刻， 编号）均衡 |
| Decode 选择 | 邻域（≤ B_NOC/B_HBM）内单位 NPU 边际时延最小，平局轮转 |
| KV 层次 | 完整片上 ↔ 完整远端，整会话粒度逐入逐出 |
| 命中路径 | 本地零开销 / 跨片整份 NoC 迁移 / 最近边缘端口远端读回 |
| 淘汰 | FIFO：（完成时刻， 会话标识），逐 NPU 收敛，活跃保护，写远端确认后释放 |
| 水位 | R_kv token 逐 NPU 保留，完成后恢复 |
| 容量不足 | 挂起等待、逐决策点重查，不改映射 |
| 历史感知 | 仅容量过滤层面的间接感知，驻留位置不进选点目标 |

一句话概括：**用边缘 NPU 挂接的统一远端池替代"删除-重算"，以完整会话 KV 的
FIFO 逐入逐出保存全部历史；映射算法承自 FACE，容量从守门员升级为准入过滤器。**
