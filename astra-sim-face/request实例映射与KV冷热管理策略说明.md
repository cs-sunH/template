# FACE 基线策略说明：请求实例映射与 KV 冷热管理

> 本文从体系结构、算法—软件映射与仿真三个视角，给出 FACE 式基线策略的通用说明。
> 全文与具体硬件配置、模型规格无关：拓扑规模、算力/带宽/容量、模型层数与维度等
> 均以参数符号表达，任何满足前提的晶圆级系统都可套用。

## 1. 策略定位

FACE 式基线代表"**共享实例池上的逻辑 P/D 解耦**"，是五版本演化链
（WSC-LLM → FACE → SH-1.0 → SH-2.0 → SH-3.0）的第二站。相对 WSC-LLM 的静态
物理分区，它做了两处本质松绑：

- **实例不再有固定角色**：所有实例构成一个统一的服务池，同一实例可在同一轮迭代中
  既执行队首预填充块、又服务活跃解码批。P/D 分离不再体现为资源池的硬隔离，而是
  体现为**两个阶段各自独立选点**；
- **映射开始感知负载与邻域**：Prefill 选择以"未完成工作量"为主键；Decode 选择
  以"预测迭代时延增量"为目标，并把候选限制在通信可达的邻域内。

但历史 KV 仍是**被动的恢复对象**：它的位置与代价不进入任何映射目标。实现中附带
的会话 KV 两态管理层（驻留/删除 + 重算）只为让多轮会话可仿真，不改变这一本质。

## 2. 系统模型与记号

### 2.1 体系结构前提

- **晶圆级芯片**：R 行 × C 列二维 Mesh，N = R·C 个 NPU；
- **每 NPU**：峰值算力 F；本地 HBM 带宽 B_HBM、访问时延 λ_HBM、容量 C_HBM；
- **片间链路**：相邻 NPU 间带宽 B_NOC、逐跳时延 λ_NOC；
- **远端内存**：本策略不启用内存扩展——KV 只能驻留片上或被删除。

### 2.2 实例池与邻接图

芯片被划分为 m 个**互不重叠、铺满整片、等大的轴对齐矩形实例**，每实例 t 个 NPU
（TP = t）。所有实例身份对等，同时承担 Prefill 与 Decode。实例间共享物理边即
邻接，构成带边权的实例图：边权初始为 1（跳数），图中两实例的**加权距离**取最短路。

**可调度距离上限**（算法核心参数，源自 FACE 论文的设计准则）：

> D_limit = B_NOC / B_HBM

即"实例间链路带宽相对本地内存带宽的倍数"。它表达了这样的工程判断：若 Decode
实例离 Prefill 实例太远，跨实例 KV 交接的片上传输时间将超过直接从本地 HBM 重读
的时间，交接便不划算。由于 B_NOC > B_HBM，D_limit 是一个大于 1 的实数；在边权
为 1 的实例网格上，它等价于"允许 1~2 跳的邻域"——例如从网格中心实例出发可达全部
实例，而从角落实例出发则排除对角与对侧的远端实例。

### 2.3 模型与 KV 容量记号

设模型 L 层、隐藏维 d、注意力头数 H、元素字节 b：

- 每 token KV 字节数 B_KV = 2·L·d·b；长度 h 的上下文对应 B_KV(h) = 2·L·h·d·b；
- 注意力头按**整头**划分到 t 个 NPU（H 不整除时前若干 NPU 各多一头），同一会话
  在各 NPU 上的 KV 分片可以不等——**容量检查逐 NPU 进行**；
- 逐 NPU 账本：剩余 = C_HBM − 权重分片 − 驻留 KV 分片 − 已承诺预留分片。

### 2.4 负载记号

会话多轮：首轮带绝对到达时刻，后续轮在"上轮 Decode 完成 + 思考间隔"后到达。
每轮派生量：h_hist（上轮最终上下文）、h_pre = h_hist + 本轮输入、
h_fin = h_pre + 生成长度。预填充按 p_chunk（参数）分块。

## 3. 请求实例映射策略

### 3.1 Prefill 阶段选择（请求到达时）

在全部 m 个实例中取排序键字典序最小者：

> **（队列中全部请求的剩余预填充块数之和， 最近一次承接新请求的时刻， 实例编号）**

三级平局规则：

1. 剩余块数最少者优先（负载均衡主键——比 WSC-LLM 的"请求数"更精细，长请求贡献
   更多块数）；
2. 块数相同 → 最近承接时刻最早者优先（最久没接到新活的实例优先；从未承接过者
   视为最早，最优先）；
3. 仍相同 → 实例编号最小（等大实例下纯属确定性破平，保证结果可复现）。

每个实例内部是 FCFS 队列；同一时刻多个请求到达时逐个处理，每个请求都对全实例
做一次快照后再选择。

### 3.2 Decode 阶段选择（Prefill 完成边界）

某个请求的预填充全部完成后，**独立地**为其选择 Decode 实例：

**第一步：邻域过滤。** 候选集 = 与该 Prefill 实例加权距离 ≤ D_limit = B_NOC/B_HBM
的实例（含自身）。

**第二步：增量代价评估。** 对每个候选 j，用预测模型比较"加入本请求前后"的一次
混合迭代时长：

- 当前状态：(是否有预填充工作， 活跃解码批大小 b_j， 批内最长上下文 ℓ_j)；
- 加入后：(同上， b_j + 1， max(ℓ_j, 本请求预填充上下文 h_pre))；
- **增量代价** Δ_j = T(加入后) − T(加入前)；
- **单位 NPU 代价** = Δ_j / t（按实例规模归一，使不同大小实例可比）。

**第三步：选择与平局。** 取单位 NPU 代价最小者；若出现**精确相等**的多候选，
按实例编号升序列出并以**轮转方式**轮流选取（保证严格平局时负载被均匀轮摊，而非
永远压在编号最小的实例上）。

容量角色是**守门员而非目标**：候选需满足逐 NPU 的"剩余 + 可回收 ≥ 需求"可行性
（与第 4 节一致），但 HBM 余量不改变代价排序，只淘汰不可行者。

### 3.3 混合迭代调度

选点之后，同一实例内按"混合迭代"推进：

- 实例空闲且（预填充队列非空 或 活跃解码非空）时启动一次迭代；
- **一次迭代 = 队首请求的 1 个预填充块（若有）+ 全部活跃解码请求各推进 1 个 token**；
- 迭代时长按（是否有块、批大小、批内最长上下文）查预测表得到；线性层部分由
  "块 token + 批 token"共享，预填充注意力与解码注意力两段重叠取较长者；
- 预填充完成的请求立即进入 Decode 准入流程（同轮内后续完成者可见其排队）；
- 解码请求每轮生成 1 个 token，生成长度归零即完成、退出批，并触发同会话下一轮
  的到达计时。

### 3.4 与 WSC-LLM 的关键对照

| 维度 | WSC-LLM | FACE |
| --- | --- | --- |
| 实例角色 | 物理固定 P/D 分区 | 共享池，逻辑解耦 |
| Decode 归属 | 静态路由唯一确定 | Prefill 完成后动态选点 |
| 选择主键 | 排队请求数 | 剩余块数 / 预测时延增量 |
| 候选范围 | 全部 Prefill 实例 | 加权距离 ≤ B_NOC/B_HBM 的邻域 |
| 网络感知 | 无 | 邻域约束（跳数意义上） |

## 4. KV 冷热管理策略

### 4.1 两态模型

与 WSC-LLM 的会话层相同：每个会话的 KV 要么**完整驻留在某一实例**（RESIDENT），
要么**被删除**（EVICTED，保留逻辑上下文长度）。无远端内存、无部分驻留态、无容量
驱动的重映射。

### 4.2 历史复用决策（新请求选定 Prefill 实例后）

按会话状态四选一：

1. **无历史**：新会话首轮，直接预填充；
2. **本地命中**：KV 在选定实例——零开销复用；
3. **跨片迁移**：KV 在其他实例——整份 KV 按相对 TP 编号一一配对迁移（目标端先
   落位、源端后释放），确定性维度序最短路由；
4. **重算**：KV 已删除——腾出空间后全部历史 token 作为额外预填充块重算（优先于
   本轮输入）。

### 4.3 P→D 交接

Prefill 与 Decode 落在不同实例时（FACE 两阶段独立选点的自然结果），发生一次
**整份 KV 交接**：按 h_pre 计算总字节，逐相对 TP 编号配对发送；目标端完成容量
检查（水位 + 物理适配）后落位。同实例则零开销复用。

### 4.4 淘汰规则与水位

- **淘汰顺序（近似 LRU）**：（最后完成时刻， 会话标识）升序——最早完成的先删，
  平局按会话标识字典序；候选仅限"已完成且非活跃"的本实例驻留会话，触发需求的
  请求自身被保护；
- **逐 NPU 收敛**：反复淘汰队首并重查，直到实例内**每个 NPU** 同时满足需求；
- **容量纪元驱动的重试**：每个实例维护一个容量变化计数器；被阻塞的请求按纪元
  去重重试，避免对纯活跃 KV 的无效自旋；
- **等待而非改道**：Decode 交接被容量阻塞时，该请求重排到等待队列尾部继续尝试，
  同实例后续等待者仍会被处理；**已选定的 Prefill/Decode 目标不因容量压力改变**；
- **KV 保留水位**（参数 R_kv）：每实例为"R_kv token 的完整 KV"逐 NPU 保留空闲，
  每次请求完成后恢复，必要时级联淘汰冷会话。

## 5. 算法—体系结构映射分析

1. **邻域约束 ↔ 链路-内存带宽比**：D_limit = B_NOC/B_HBM 把"跨实例交接是否
   划算"编码为图距离约束——链路越快（相对本地 HBM），允许的 Decode 距离越远。
   这使映射决策以一个标量吸收了关键的网络/内存配比，而不必在线估计传输时间。
2. **增量时延目标 ↔ Roofline 预测**：解码选点把"新请求加入活跃批"的边际代价
   显式建模：批大小 +1 的线性层增量与"批内最长上下文被拉长"的注意力增量，由
   计算/访存双界预测给出。这与连续批处理的实际迭代结构同构，是**面向批处理
   的负载感知**，超越了 WSC-LLM 的请求数均衡。
3. **混合迭代 ↔ 计算-访存重叠**：同实例同迭代内"1 块预填充 + 1 token 全批解码"
   的组织，使线性层部分被两类 token 共享摊薄、两段注意力按较长者计——实例的
   算力与 HBM 带宽同时被两类工作填充，避免纯 P 或纯 D 阶段的资源空转。
4. **核心局限**：预测模型只看计算与访存的"时间"，不看 KV 的"空间与位置"——
   历史 KV 在哪、迁移/重算的代价多大都不影响选点；两阶段独立选点还天然引入
   P→D 整份交接的额外网络流量。这构成 SH 系列改进的起点。

## 6. 仿真视角

- **双层架构**：Python 规划器给决策、C++ 离散事件引擎给物理时间；支持离线
  （规划器逻辑时钟 + 预测表）与在线闭环（引擎时钟权威，决策边界为到达/预填充
  完成/解码完成/请求完成）两种运行方式。在线模式下预测表被**冻结为标定常数**
  （其覆盖范围由输入负载预先导出），完成时刻由真实物理决定。
- **预测表（LUT）**：条目键为（实例规模， 预填充块长 p ∈ {0, p_chunk}， 解码批
  大小， 上下文长度），上下文按二次幂分箱、取最近箱（等距取较小箱）控制表规模；
  表按需懒生成并设缓存上限。
- **迭代时长公式（Roofline 结构）**：
  T = T_linear + max(T_prefill_attn, T_decode_attn)，
  每项 = max(算子量/聚合算力, λ_HBM + 字节量/聚合带宽)，聚合规格 = t × 单 NPU
  规格；线性部分覆盖权重读写与激活读写，注意力部分随"块长 × 可见上下文"或
  "批 × 最长上下文"增长。
- **事件序**：同一时刻的事件先处理完成类、再处理到达类、最后启动新迭代；到达
  按输入序逐个快照选点。
- **物理建模**：逐 NPU HBM 流体争用（并发用户均分 B_HBM）、拥塞感知网络
  （逐跳时延累加、确定性维度序路由）、同 NPU 计算串行、跨 NPU 通信依赖同步。
- **可观测指标**：逐请求 P/D 归属与时刻、逐实例选点时的全候选代价证据、KV 事件
  流（命中/迁移/删除/重算）、逐 NPU 水位、时延分布与吞吐、每批决策与图的摘要
  校验值。

## 7. 策略小结

| 维度 | 做法 |
| --- | --- |
| P/D 组织 | 共享实例池，逻辑 P/D 解耦，两阶段独立选点 |
| Prefill 选择 | （剩余块数， 最近承接时刻， 实例编号）字典序最小 |
| Decode 选择 | 邻域（距离 ≤ B_NOC/B_HBM）内单位 NPU 增量时延最小；精确平局轮转 |
| 迭代组织 | 混合迭代：1 块预填充 + 全批解码各 1 token |
| KV 层次 | 片上驻留 / 删除重算，两态 |
| 淘汰 | 近似 LRU：（完成时刻， 会话标识），逐 NPU 收敛，活跃保护，容量纪元去重重试 |
| 水位 | R_kv token 保留水位，完成后恢复 |
| 容量不足 | 等待/重排队，不改已选目标 |
| 历史感知 | 无（KV 位置不进决策） |

一句话概括：**以共享池 + 邻域约束 + 边际时延目标取代静态分区，让映射首次感知
负载结构；但历史 KV 仍是被动的恢复对象，P→D 独立选点还引入整份交接流量。**
