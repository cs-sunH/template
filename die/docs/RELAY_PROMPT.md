# Codex Cloud 换账号续接提示词

> 在 A 或 B 账号新建一个 Codex Cloud Task，选择 `cs-sunH/template` 仓库，确认任务基于最新共享集成分支，然后粘贴以下提示词。

```text
请继续开发此仓库的 die/ 子项目，并严格执行 die/AGENTS.md。

1. 先读取 die/docs/PROJECT.md 和 die/docs/HANDOFF.md。
2. 检查当前 Git 分支、HEAD、工作区状态与 GitHub 共享集成分支最新提交；
   确认已包含上一次交接的已合并代码。无法核实时先报告，不要盲目覆盖。
3. 读取 die/ 中的实际代码和测试，从 HANDOFF.md 的 Next Step 继续。
   不重复已完成且经验证的工作，不自行猜测尚未明确的项目目标。
4. 将工作划分成小的、可验证的阶段，执行相应测试。
5. 结束前更新 HANDOFF.md，说明完成内容、下一步、决定、测试结果和阻塞。
6. 尽可能提交代码和交接文档并创建 PR；如果不能推送，
   告诉我需要在云端 UI 完成的操作。只有成果已合并到共享分支才标记可接棒。
7. 最终报告提交 SHA、PR 合并状态、测试结果和接棒准备状态。
```

## 人工接棒顺序

1. 上一账号结束时检查代码和 HANDOFF.md 是否一起提交。
2. 有 PR 则先合并到共享集成分支（初始为 `main`）。
3. 在 GitHub 确认交付 commit SHA 和 CI 检查结果。
4. 切换 Plus 账号，在 Codex Cloud 创建**新任务**并读取最新代码。
5. 粘贴上面的提示词；若 HEAD 不包含交付提交，应先处理版本不一致。

注意：自动检查流程不会代替人合并 PR，也不能让另一个账号自动获得旧账号的 Session。
