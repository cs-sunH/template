# WSCLLM-LRU workspace v2 promotion audit

Date: 2026-10-14
Read-only source audit at branch `codex/die-os-lifecycle-20261014`, HEAD `fba3b8e`. The base WSCLLM workspace-v2 path is implemented; WSCLLM-LRU does not yet contain its workspace protocol or ledger. This report describes the smallest safe port while keeping LRU policy and transfer semantics intact. No LRU production/test source or tracked file was edited, and tests were not run.

## Finding

The existing base path provides a reusable **versioned capacity handshake and rank-local lease lifecycle**. The LRU port can use that protocol, but it must adapt capacity decisions inside the LRU manager and its online scheduler. In LRU, reclaimed KV becomes a `remote_store` transfer and a remote-pool balance; base WSCLLM's cold-delete behavior is not a valid implementation for LRU.

Workspace is an external, temporary fit hold. It must stay out of resident-KV bytes, request reservations, remote-pool balances, KV transfer totals, and journal resident/remote deltas. The full capacity check is model weights + resident KV + request reservation + active workspace, per rank.

## Reusable base implementation

- `astra-sim-wscllm/astra-sim/workload/WorkspaceAdmission.hh` owns absolute active workspace bytes and a monotonically increasing rank revision. A lease is keyed by rank/node/generation and releases once; acquire returns `Acquired`, `Blocked`, or `Impossible`. Admission checks model weight, Python-reported resident KV and reservations, and already-held workspace together (see `try_acquire` and snapshot validation around lines 21–37, 115–119, 151–203, 205–249).
- `DieModelAdapter` compiles/prepares once, gets `hbm_workspace_peak_bytes`, then passes that same immutable Plan through pre-issue admission and execution. The lease remains in the active record until the Plan terminal callback; it is released before Workload terminalization so the same-tick deferred issue pass can use the capacity again (`DieModelAdapter.cc:92–168`). Explicit cancellation and teardown must retain this ownership lifetime.
- `Workload::issue_dep_free_nodes` admits only a real GPU coarse COMP before taking the graph node or occupying the GPU. `Blocked` leaves it free for a later issue pass; `Impossible` is an error. Timer, CPU and `ControlMarker` bypass the workspace path (`Workload.cc:415–462`). Keep LRU's already-validated marker behavior as-is; the workspace path applies only to typed COMP Plans.
- `Sys` constructs one ledger for each `coarse_die_v2` rank and rejects an explicit `SH_WORKSPACE_ADMISSION=off` for that backend (`Sys.cc:913–936, 1065–1070`; `Sys.hh:369–376`). Online C++ requires a complete, rank-ordered, all-coarse or all-legacy run (`main_online.cc:1441–1465`), sends the absolute full-rank view on v2 (`main_online.cc:586–611`), validates the returned revision-bound snapshot before commit, installs all ranks before issue, and retries the union of changed-capacity and touched ranks (`main_online.cc:1730–1800`, `GraphBatchCommitter.cc:354–402, 1849–1904`). `DecisionMailbox`, `DecisionBridge`, and `ParsedGraphBatch` carry and validate schema v2 plus the full rank table.
- The base Python `online_service.py` selects `required` automatically for `coarse_die_v2` and rejects disabling it. `decision_bridge.py` uses response/request/ack schema version 2 in required mode; it binds `delivery_sequence`, `source_delivery_sequence`, `batch_id`, workspace revision echo, and the required capacity snapshot. `OnlineSchedulerBase` validates the complete sorted rank table before mutations; `WscLlmOnlineScheduler` installs the external view before policy/KV work, increments affected `capacity_epoch`s, and appends the authoritative post-decision capacity snapshot.
- Base `session_kv_manager.py` stores workspace revision/bytes in separate external maps, validates every rank before an atomic update, exposes a stable `rank_ids` view and capacity snapshot, and uses `_fit_remaining` / `_fit_insufficient` for admission. Its incremental/full invariants enforce KV + workspace <= capacity. The no-LRU empty-fit and candidate-removal behavior is specific to that manager and must not be copied to LRU (`session_kv_manager.py:581–583, 600–693, 978–1010, 1408–1487`).

## LRU behavior the port must preserve

- LRU `NodeHBMState.used_bytes` is weights + resident KV + reserved request bytes. Remote KV is accounted separately in `_remote_bytes_by_rank`; `_remote_add` and `_remote_remove` update that pool and journal deltas. Workspace must not be added to either account.
- `ensure_physical_fit` uses whole-session LRU victims: completed, inactive, fully-local sessions on the target instance, ordered by `(last_completion_ns, session_id)`. Each victim is moved remote by `_evict_session`: remove its full local shard vector, add the exact vector to remote pool accounting, and return a `remote_store` KVTransfer. Keep that eligibility, order, one-victim-at-a-time convergence, and graph emission (`session_kv_manager.py:935–963, 1757–1835, 2114–2285`; prior source audit: `die/docs/analysis/handoff-runtime-20261014/workspace-python-lru-audit.md`).
- LRU's feasibility margin includes protected/active local sessions and reserved request bytes, none of which a cold-session eviction can reclaim. Its empty-instance overflow currently raises `ValueError`; the base WSCLLM manager instead has a permanent-infeasible result. Preserve LRU's exception contract for a request that cannot fit without workspace. If a request only cannot fit because of the current workspace hold, return a temporary block with no eviction and retry after a later workspace revision.
- `prepare_history` has four paths: new/no history, local same-instance hit, local cross-instance NoC migration, and remote restore. Each calls fit first. In the remote branch, state activation and remote-pool debit happen only after fit succeeds (`session_kv_manager.py:2460–2783`). A workspace-blocked restore therefore must leave the session remote and its exact pool debit unchanged, with no restore transfer. A later fit must restore once and debit exactly the remote shard bytes.
- The journal transaction snapshot includes manager ranks, sessions, reservations, event tails, remote balances, metrics parts, and invariant ledgers (`session_kv_manager.py:1883–1980`). Workspace view is external bridge state: keep it outside the transaction snapshot so a manager rollback restores LRU state without rolling back the newer C++ absolute view. Extend incremental and full capacity checks to enforce weights + resident KV + reservations + workspace <= rank capacity.
- The LRU online scheduler has additional reservation net-credit, capacity-epoch retry, store/restore emission, pending store tails, completion gates and ordering (`wsc_llm_online_scheduler.py:1407–1567, 1621–1650, 1906–1950`; graph transfer tests below). A blocked history fit releases its Decode reservation and clears credit; preserve that behavior. A blocked history decision may still flush a *separate, previously committed* decode-reservation eviction. Tests should isolate the history restore when asserting that no restore/store was produced by the blocked restore itself.

## Minimum safe integration sequence

1. Port the base C++ v2 protocol/lifecycle as targeted changes: add `WorkspaceAdmission.hh`; add the per-rank `Sys` ledger and coarse-mode gate; adapt `DieModelAdapter` to prepare once, acquire before graph take/occupy, carry the lease into the active execution record, and release on completion/cancel/teardown. Keep LRU's Workload callbacks, transfer joins and current `ControlMarker` path. Do not replace LRU `Workload.cc` wholesale with the base file.
2. Port the v2 bridge plumbing as a coherent unit: `DecisionMailbox`, `DecisionBridge`, `ParsedGraphBatch`, `GraphBatchCommitter`, and `main_online.cc`. Keep the protocol explicit and fail-closed: all ranks use the same schema; each request carries every rank's absolute revision/bytes; each response includes every rank's capacity, weights, resident KV and reserved bytes plus the echoed workspace revision; validate all ranks before any install; install after Python's batch mutations and before issue; wake on capacity changes even when there are no new nodes. Add the matching LRU CMake target(s).
3. Port the Python mode and bridge hooks: `_workspace_admission_mode`, v2 request/response/ack checks, `OnlineSchedulerBase` full-rank validation and extension hooks, then LRU scheduler application before policy. Use LRU topology rank IDs to map changed ranks to instances and bump those `capacity_epoch`s. Do not transplant the base `WscLlmOnlineScheduler` policy.
4. Add LRU's external view to `session_kv_manager.py`: stable rank IDs; absolute revision/byte maps; exact full-rank validation; reject stale revision or changed bytes at the same revision; validate the complete new view before changing any rank; return changed ranks; produce a capacity snapshot with the existing resident and reservation meanings. The external workspace maps stay outside `_journal_rollback_snapshot`.
5. Adapt `ensure_physical_fit` rather than replacing it. Preserve the existing non-workspace empty-instance `ValueError`, LRU eligibility/order and protected/active/reservation rules. Compute fit from remaining bytes minus external workspace. The eviction feasibility test must subtract workspace alongside protected/active residency and reservations. If the request still cannot fit after every eligible victim is reclaimed under the current hold, and it would fit without that hold, return a workspace wait without making a remote-store transfer. If it can fit with the hold after reclaiming a prefix, evict that minimum LRU prefix through the existing `_evict_session` path. Add a distinct internal `blocked_by_workspace` flag if useful for classification; the online policy can continue using its existing `admission_blocked`/`capacity_epoch` retry contract.
6. Let all existing fit callers inherit the rule through `ensure_physical_fit`: request reservation, history preparation (all four branches), prefill/decode growth, and Prefill-to-Decode movement. Add combined-capacity checks to incremental and full invariants. Keep workspace out of HBM snapshots used for KV accounting and out of remote pool/journal deltas.
7. Validate in layers, then run a production LRU online E2E with workspace required. Keep legacy/v1 behavior for non-coarse runs and demonstrate that coarse cannot silently select `off`. The E2E should include workspace acquire/release, a capacity-epoch retry, memory pressure that performs a real LRU remote store, blocked remote restore followed by one successful restore, and existing store-before-restore ordering. Include cancellation/teardown so every lease releases once.

## Differences that prevent direct copying

| Concern | Base WSCLLM | WSCLLM-LRU requirement |
|---|---|---|
| Reclamation | Cold deletion; no remote KV transfer | Whole-session LRU remote_store; preserve session and remote pool |
| Empty-instance overflow | Returns permanent-infeasible/block result | Raises `ValueError`; preserve unless explicitly redesigned |
| Fit margin | External workspace subtracts from fit headroom | Also subtract from LRU reclaimability after active/protected residency and reservations |
| History | No LRU remote-pool lifecycle | Four paths; blocked remote restore must not mutate/debit/emit restore |
| Rollback | External view separate from manager state | Same ownership split, but rollback must restore LRU remote balances, transfer-related manager state and journal ledgers |
| Scheduler | Base admission hooks and simple capacity wakeup | Keep net-credit pre-reservation, LRU store/restore, pending gates, store-before-restore and capacity epochs |
| C++ sources | Workspace changes integrated in Workload/adapter/bridge | LRU files have their own callback/marker implementation; port targeted hunks and preserve existing marker repair |

The LRU checkout currently has none of the workspace protocol symbols (`rg` over `astra-sim-wscllm-LRU` finds no `WorkspaceAdmission`, `workspace_state`, `workspace_capacity_snapshot`, or `active_workspace_bytes`). Its online bridge remains v1, and its scheduler does not install a workspace view. This is an implementation gap, not a failing test result.

- C++ `astra-sim-wscllm/astra-sim/workload/execution_driven/tests/workspace_admission_test.cc`, `parsed_graph_batch_test.cc`, and `graph_batch_committer_test.cc` cover lease accounting, strict snapshot parsing, atomic preflight/install and capacity wakeup. Adapt the cold-delete assertions to expect LRU `remote_store`/pool accounting.

**Run/extend LRU-specific coverage:**

- `test_tiered_eviction_sequence.py`: strict LRU order and over-release; protected, active and reserved fit margins. Add workspace pressure and assert only the minimum eligible LRU prefix moves remote.
- `online/test_admission_net_credit.py`: especially `test_net_success_then_history_blocked_releases_and_clears` and `test_scheduler_net_credit_flow_on_real_manager`; add changed-workspace-epoch retry and no stale reservation credit.
- `online/test_kv_transfer_emission.py`: remote_store/remote_load, full-layer restore and joins; assert a blocked restore emits no restore transfer and does not debit remote bytes.
- `online/test_store_restore_ordering.py`: existing store-tail and restore barriers; retry must preserve ordering and consume each pool/restore ledger once.
- `test_kv_delta_journal.py` and `test_wscllm_kv_incremental_invariants.py`: rollback/conservation and incremental-vs-full invariants; add workspace outside transaction snapshot and combined-capacity rejection.
- Finally run the LRU C++ Online build/CTest and a real Python↔C++ coarse v2 online fixture with memory pressure and cancellation. A manager-only test does not prove bridge revision echo, changed-rank wakeup, or transfer ordering end to end.
