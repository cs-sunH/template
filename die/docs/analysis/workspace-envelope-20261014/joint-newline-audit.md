# Active JOINT coarse-die/workspace integration audit

Audit date: 2026-10-14  
Repository: `/workspace/template`, branch `codex/die-workspace-envelope-20261014`, HEAD `fecf81c5574755209c5d58ecdb982843ff349042`.

This is a read-only source audit. No JOINT source or test result was changed or reused. The requested integration target is the active `astra-sim-joint`, not `astra-sim-joint_old`.

## Finding

The active JOINT tree has the legacy `DieModel` execution path, substantial independent pipeline/projection behavior, and a typed dual-ledger path. It does **not** yet have a tracked coarse-die task/Plan input, workspace capacity protocol, admission lease, or capacity-triggered retry path. Existing `die_spec` / `DieExecution` code cannot be treated as a coarse-die adapter: its Plan, action, and hardware types are from the legacy `DieModel` library.

The smallest safe integration is additive: link the canonical coarse C++ library into `AstraSim`, add a separate coarse task/Plan adapter and runtime/config selection, and preserve the JOINT pipeline contract, native projection, ordinary node/NoC/HBM lifecycle, and ledger publisher unchanged. The capacity protocol and ready-node preflight need their own changes; merely compiling and linking coarse code would not provide workspace enforcement.

## What is present in active JOINT

* `DieModelAdapter` is a per-`Workload` bridge for `shared_ptr<const DieModel::DieOpSpec>` and cached `DieModel::DiePlan` objects. It requires `Sys::die_runtime`, computes `DieModel::plan_cache_key`, compiles via `DieModel::compile`, and starts a legacy `DieExecution` ([DieModelAdapter.hh](../../astra-sim-joint/astra-sim/workload/DieModelAdapter.hh#L7), [DieModelAdapter.cc](../../astra-sim-joint/astra-sim/workload/DieModelAdapter.cc#L50)). `Sys` parses only the `die` backend and constructs its legacy Hardware/PlanCache ([Sys.cc](../../astra-sim-joint/astra-sim/system/Sys.cc#L758), [Sys.hh](../../astra-sim-joint/astra-sim/system/Sys.hh#L329)).
* Graph input is typed around `op_role` and optional `die_op_spec`; the parser validates the legacy spec and the real compute dispatch fails closed when it is missing ([GraphSource.hh](../../astra-sim-joint/astra-sim/workload/execution_driven/GraphSource.hh#L75), [ParsedGraphBatch.cc](../../astra-sim-joint/astra-sim/workload/execution_driven/ParsedGraphBatch.cc#L217)). No tracked `coarse_task`/coarse Plan field is present.
* Die dispatch preserves timer, CPU, and control-marker paths, then passes a real compute node to `DieModelAdapter`; the marker remains the legacy 1-op/1-byte micro-job ([Workload.cc](../../astra-sim-joint/astra-sim/workload/Workload.cc#L915)). Active-execution drain and Workload teardown already account for legacy DieExecution objects ([Workload.cc](../../astra-sim-joint/astra-sim/workload/Workload.cc#L184), [Workload.cc](../../astra-sim-joint/astra-sim/workload/Workload.cc#L1744)).
* `LocalHbmBandwidthModel` already has a dedicated `DIE_COMPUTE` internal job path. It drains service units separately from actual bytes, does not charge a second outer completion or a FLOP leg, and can cancel jobs by sink ([LocalHbmBandwidthModel.hh](../../astra-sim-joint/astra-sim/workload/LocalHbmBandwidthModel.hh#L39), [LocalHbmBandwidthModel.cc](../../astra-sim-joint/astra-sim/workload/LocalHbmBandwidthModel.cc#L821)). This is a reusable integration point only for a coarse executor whose HBM demand semantics match it; it is not capacity admission and does not hold workspace.
* Pipeline behavior is a separate run-frozen contract. `PipelineKernelContract` pins projection/descriptor/protocol versions, model version, timer whitelist, and window parameters ([PipelineKernelContract.hh](../../astra-sim-joint/astra-sim/workload/execution_driven/PipelineKernelContract.hh#L21)). `NativeProjection` consumes that contract and implements JOINT-native projection/session semantics, while its embedded DIE plan parsing still uses legacy `DieModel::DiePlan` and `DieModel::Execution` ([NativeProjection.hh](../../astra-sim-joint/astra-sim/workload/execution_driven/NativeProjection.hh#L24), [NativeProjection.cc](../../astra-sim-joint/astra-sim/workload/execution_driven/NativeProjection.cc#L467), [NativeProjection.cc](../../astra-sim-joint/astra-sim/workload/execution_driven/NativeProjection.cc#L944)). Replacing that code with coarse runtime behavior would be a separate semantic migration, not a workspace hookup.
* JOINT has a distinct typed ledger library (`joint_ledger`, plus its Python-facing C ABI) and `WorkLedgerV2RuntimeSnapshot` translates active graph/HBM/NoC/pool activity to ledger resource rows ([CMakeLists.txt](../../astra-sim-joint/extern/joint_ledger/CMakeLists.txt#L28), [WorkLedgerV2RuntimeSnapshot.cc](../../astra-sim-joint/astra-sim/workload/execution_driven/WorkLedgerV2RuntimeSnapshot.cc#L170)). Workspace is incremental admission state; it should not be presented as a ledger HBM transfer, KV reservation, remote-pool operation, or a new joint resource domain.

## Admission and protocol gaps

The current issue order is the main integration constraint. In the Online ready pass, `Workload::issue_dep_free_nodes()` checks GPU availability and calls `issue()` ([Workload.cc](../../astra-sim-joint/astra-sim/workload/Workload.cc#L583)). `issue()` calls `take_node`, occupies the GPU resource, records issue metrics/ledger, and only then routes the COMP to the legacy die backend ([Workload.cc](../../astra-sim-joint/astra-sim/workload/Workload.cc#L694), [Workload.cc](../../astra-sim-joint/astra-sim/workload/Workload.cc#L737)). Therefore compiling/acquiring in `issue_die_comp()` is too late. Add a coarse admission preflight at the ready-candidate boundary, after resource availability but before `issue()`; only a successfully acquired Plan lease may cross into node take/GPU occupancy. A blocked candidate must remain free and must not publish `issue` or create a Workload/HBM event. `control_marker` must be recognized before preparing/compiling or acquiring workspace.

The active online request currently describes events, affected ranks, snapshots, and optional ledger/link telemetry; the response parser accepts schema-3 graph fields and a frozen `kernel_contract`. Neither shape contains an absolute workspace-state vector or a complete KV capacity view ([DecisionBridge.hh](../../astra-sim-joint/astra-sim/workload/execution_driven/DecisionBridge.hh#L61), [ParsedGraphBatch.cc](../../astra-sim-joint/astra-sim/workload/execution_driven/ParsedGraphBatch.cc#L568)). There is no `workspace_state`, `workspace_revision`, or full-rank workspace capacity installation path in the tracked active JOINT C++ protocol.

For the required v2 wiring, treat each C++ request as an absolute snapshot: send every rank's `(rank, workspace_revision, active_workspace_bytes)`. Require the response to echo the revision and provide the complete rank-indexed capacity view (capacity, weights, resident KV, reserved bytes); validate the entire view, ranks, exact nonnegative integers, echoes, and GraphBatch before mutating any ledger or graph state. Install capacities as absolute revisions, then commit using the existing formal GraphBatch transaction order: validation/preflight first; commit delta/nodes/edges/watches/alarms and the capacity snapshot without an observable partially validated state; then issue the changed and touched ranks. A capacity update that can unblock work must trigger a rank issue pass. Never interpret a malformed/partial response as zero capacity or fall back to legacy compute.

At the ready-node boundary, prepare each immutable coarse Plan once (including memoization keyed by hardware identity and normalized task), extract exact `hbm_workspace_peak_bytes`, and pass that Plan to the rank-local `WorkspaceAdmission` ledger. The lease must be owned by the live execution object and move with it; release it exactly once on normal terminal completion, explicit cancellation, or teardown. Keep the legacy DieModel adapter available under its explicit existing profile; do not coerce one Plan type into the other.

## Resolver and configuration

The active resolver recognizes legacy `die` input, derives its summary through `libdie_model_cabi.so`, and writes `resolved_die_model.json`; its accepted system profile values are `mesh_die_v1` and `tx8_reference_v1` ([config_resolver.py](../../astra-sim-joint/sh_test_mesh/config_resolver.py#L37), [config_resolver.py](../../astra-sim-joint/sh_test_mesh/config_resolver.py#L489), [config_resolver.py](../../astra-sim-joint/sh_test_mesh/config_resolver.py#L714)). C++ mirrors that legacy key set and profile validation, and `compute-cost-model` currently allows only `die`, `roofline`, and `replay` ([Sys.cc](../../astra-sim-joint/astra-sim/system/Sys.cc#L701), [Sys.cc](../../astra-sim-joint/astra-sim/system/Sys.cc#L758)). The legacy resolver also aligns its local-HBM capacity profile to legacy die-derived hardware; it does not derive workspace or expose dynamic per-rank capacity.

Add an explicit coarse-v2 model/config branch rather than expanding the meaning of `die` silently. Give its hardware schema/C ABI discovery and resolved-config artifact an explicit name; the Python resolver must not reimplement C++ rate/workspace formulas or feed coarse hardware through `die_model_cabi`. Mirror accepted keys, profile tokens, schema checks, conflicts, and defaulting rules in Python and `Sys`, failing closed if a coarse request has only a legacy die config or vice versa. Preserve existing legacy `die` fixture and output behavior. The current worktree has an uncommitted `astra-sim-joint/extern/die_model/CMakeLists.txt` edit adding `add_subdirectory(coarse)` and an untracked `extern/die_model/coarse/` directory; this audit treats those as in-progress root WIP, not as committed JOINT implementation.

## Minimal additive implementation shape

1. Sync the canonical pure library and add/link its `coarse_die` static target to active `AstraSim`. Keep `die_model`, `joint_pipeline_core`, `joint_projection`, and `joint_ledger` targets and their ownership boundaries intact. Expose the coarse headers only through the new target. A resolver-facing coarse C ABI may be built separately; do not replace the legacy `die_model_cabi` contract.
2. Add a separate coarse task field/value to the parsed graph representation, with exact schema/type checks and explicit model selection. Do not reinterpret `die_op_spec` as a coarse task. Keep marker nodes on their current physical path and bypass Plan preparation/admission entirely.
3. Add a coarse runtime/config handle to `Sys` with immutable validated hardware and plan cache; add a distinct adapter/execution object. Prepare/cache once, acquire the workspace lease before graph take and GPU occupancy, retain the immutable `shared_ptr<const coarse_die::Plan>` plus lease through execution, then release the lease once on each terminal/cancel/teardown path. Ensure the adapter remains alive while its timer/HBM callbacks are cancelled, and include live coarse work in Workload drain checks.
4. Keep physical work and JOINT accounting routed through existing owners: outer COMP issue/terminal and ledger lifecycle stay one logical node; real internal HBM requests go through `LocalHbmBandwidthModel` only if their service/actual-byte semantics map exactly. Do not create extra outer completions, duplicate work-ledger records, or mutate pipeline contract state. Workspace reservation is admission-only and must not inflate HBM payload, remote-memory bytes, KV occupancy, or pool transfer accounting.
5. Add absolute workspace state/capacity fields to the online bridge and typed response/batch parser. Extend the formal committer preflight/commit so all ranks and echoes are validated before installation, preserving existing batch validation purity; after install, retry changed and touched ranks. Preserve frozen `PipelineKernelContract` checking and protocol identifiers/sequence rules. Schema/profile bumps are explicit on both peers.

## Suggested focused tests

These are target recommendations only; no tests were run for this audit.

* Keep and continue running current `JointPipelineWindowTest`, `NativeProjectionCApiTest`, `joint_ledger` tests, and current legacy die adapter/lifecycle/HBM tests as unchanged regression targets. Their existing results do not establish coarse compatibility.
* Add a `CoarseDieWorkspaceAdmissionTest` for exact integer extraction, zero/positive workspace, fit/block/impossible, capacity replacement/revision checks, duplicate owner rejection, move/RAII release, and double-release detection. Exercise the canonical coarse Plan and WorkspaceAdmission, not a handwritten fake Plan summary.
* Add `AstraSim_Analytical_Congestion_Aware_CoarseDieAdapterTest` using the existing real-Sys/EventQueue hermetic pattern: (a) Plan preparation once/cache hit, (b) capacity-blocked and impossible ready COMP remain untaken/unoccupied with no issue ledger event, (c) lease exists while the immutable Plan is active, (d) completion/cancel/teardown release exactly once, (e) zero-workspace/control marker bypasses coarse prepare and preserves legacy 1B semantics, (f) HBM callback cannot terminalize the outer node twice.
* Extend parser/committer/bridge fixtures with response echo/revision mismatches, missing/duplicate/out-of-range ranks, negative/floating/overflow byte values, partial capacity arrays, malformed task fields, stale revisions, and an atomic-failure assertion proving no NodeStore/KV/capacity mutation occurs. Add a valid batch test proving the capacity snapshot is installed before touched-rank retries and that changed-but-untouched ranks also retry.
* Add a full ready-pass fixture with two independently ready positive-workspace Plans and a real free NodeStore/empty event queue. Verify blocked nodes stay ready, GPU and workspace occupancy remain zero, preparation is memoized, no event is queued, and a later capacity/revision installation retries them. This exercises the required scheduler integration; a parser/unit test alone cannot prove the lifecycle.
* Run the official JOINT Online fixture against the explicitly selected coarse model only after the focused tests. Acceptance should require positive Plans, observed live lease holds (not only end-of-batch totals), balanced acquire/release and exactly-once terminals, rank/revision echoes and full capacity validation, preserved ledger/pipeline schema, and C++/Python clean exit. Existing JOINT tests or the prior archived JOINT tree are not substitutes.

## Limits

This report is a source-level integration audit, not a build or runtime result. It does not claim that the active JOINT workload generator emits a coarse task, that the JOINT scheduler consumes workspace state, or that a production coarse-die Online run works. The `coarse_die` workspace contains the compiler/Plan/Runtime APIs needed for an adapter, but the active tracked JOINT implementation still lacks the adapter, pre-take hook, admission ledger, and protocol path described above.
