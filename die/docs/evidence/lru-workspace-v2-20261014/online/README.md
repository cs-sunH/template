# WSCLLM-LRU workspace-v2 Online evidence

This package records the final post-alias-fix production Online E2E and selected earlier attempts. The final run used the LRU-specific `session_lru_tiered` policy, the official 4x2 RingTopology with P ranks 0–3 and D ranks 4–7, and 144,000,000,000 bytes/rank from the resolved coarse C ABI hardware. The model is one-layer MHA/GQA1: hidden 512, FFN 1,024, vocabulary 512, Q=4, KV=4, head dimension 128; prefill 64 and decode 1. No capacity or workspace demand override was used.

The successful run is in `final-run/`. C++ and Python exited 0; the final auditor exited 0. Three schema-v2 request/response/ack exchanges succeeded, `REQUEST_COMPLETE` was observed, all 124 graph terminals completed, and the service accepted/completed one request. All eight compiled plans had positive workspace: 65,536 bytes on P ranks and 1,024 bytes on D ranks. Workspace revision changes infer ten balanced acquire/release pairs per rank; bridge-boundary snapshots show zero active workspace, so no positive live lease is claimed as directly sampled.

The audit found no missing pre-port LRU metric keys or value-type changes. Typed rank/local-HBM/coarse metric windows and capacity windows passed. The LRU baseline emits flat-zero HBM watermark summaries without planner replay; base-only `window_start_ns` and `window_end_ns` are unmapped. `iteration` and `memory_anchor` were not emitted by this tiny trace.

`strace-omissions.json` records byte counts and SHA-256 for the raw strace files; raw trace contents and executable/library binaries are intentionally absent. `source-identity/metrics-alias-fix/` has the C++ agent's measured dirty-source manifest, selected patch, binary hash record, and provenance.
