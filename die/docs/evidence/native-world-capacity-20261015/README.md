The frozen projection input accepts optional `coarse_capacity_events` entries with exactly `{time_ns, resource_key, resource_index, absolute_physical_rate}`. The key names an existing coarse physical domain; the resource index uses canonical `coarse_die::resource_count`/resource enums. Time is integer ns at or after initial now, at most 2^53−1. The rate uses the canonical resource's physical units per second. Complete input is checked through empty canonical Domains before a world is created: invalid, nonfinite, negative, above-peak, unknown or hardware-disabled nonzero rates fail closed.

Events are ordered by time then input order; existing readiness/latency/forecast priorities remain unchanged and capacity events use priority 4. Runtime service reaches the event tick at the old rate and settles completions before the new rate applies. The baseline and candidate inherit the same frozen schedule. Actual service, work, busy time, credits and owner sharing remain in the existing canonical Runtime; no prediction multiplier or new timing formula is added.

It binds the consumed prefix and exact pending suffix to the frozen input, verifies domain capacities against that prefix, and checks combined forecast/capacity counters. Missing, duplicate, forged or omitted events are rejected in a disposable importer. Same-tick budget stops retain the unconsumed suffix. Inputs without capacity events retain the previous snapshot field shape and remain readable.
