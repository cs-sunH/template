# WSC-LLM 基线策略说明：请求实例映射与 KV 冷热管理

> 本文从体系结构、算法—软件映射与仿真三个视角，给出 WSC-LLM 式基线策略的通用说明。
> 全文与具体硬件配置、模型规格无关：拓扑规模、算力/带宽/容量、模型层数与维度等
> 均以参数符号表达，任何满足前提的晶圆级系统都可套用。

## 1. 策略定位

WSC-LLM 式基线代表"**静态物理 P/D 分区**"这一类最直接的资源组织方式，是五版本
演化链（WSC-LLM → FACE → SH-1.0 → SH-2.0 → SH-3.0）的起点：

- **Prefill 与 Decode 在物理上隔离**：一部分实例永久负责预填充，另一部分永久负责
  解码，两者之间用预先算好的固定路由互联；
- **在线映射决策极简**：只看 Prefill 队列的请求数做均衡，Decode 目的地由静态路由
  唯一确定，不感知请求长度、队列压力、KV 位置或内存状态；
- **KV 只有"片上驻留"与"删除"两态**：空间不足时按近似 LRU 淘汰整份会话 KV，
  被删会话再次到来时重算全部历史。

为使多轮会话流量可被仿真，实现中在基线骨架上附带了会话 KV 两态管理层；该层只提供
"驻留/删除"的容量语义，不改变基线"映射不感知历史"的本质。

## 2. 系统模型与记号

### 2.1 体系结构前提

- **晶圆级芯片**：R 行 × C 列二维 Mesh，N = R·C 个 NPU，片上网络互联；
- **每 NPU**：峰值算力 F；本地 HBM 带宽 B_HBM、访问时延 λ_HBM、容量 C_HBM；
- **片间链路**：相邻 NPU 间带宽 B_NOC、逐跳时延 λ_NOC；
- **远端内存**：本策略不启用内存扩展——KV 只能驻留片上或被删除。

### 2.2 实例划分

芯片被划分为 m 个**互不重叠、铺满整片、等大的轴对齐矩形实例**，每实例 t 个 NPU
（张量并行度 TP = t），共同承载一个模型副本。实例间共享物理边即邻接，构成实例级
网格；实例邻接图必须连通。

### 2.3 模型与 KV 容量记号

设模型 L 层、隐藏维 d、注意力头数 H、元素字节 b。则：

- **每 token 的 KV 字节数**：B_KV = 2·L·d·b（K 与 V 两份）；长度 h 的上下文
  对应 KV 总量 B_KV(h) = 2·L·h·d·b；
- **逐 NPU 分片**：注意力头按**整头**划分到 t 个 NPU（H 不能整除时，前若干 NPU
  各多承担一个头），因此同一会话在各 NPU 上的 KV 分片字节可以不等——**容量检查
  必须逐 NPU 进行**，不能只看实例总量；
- **逐 NPU 账本**：剩余空间 = C_HBM − 模型权重分片 − 驻留 KV 分片 − 已承诺请求
  的预留分片。

### 2.4 负载记号

- 会话由多轮请求构成：首轮带绝对到达时刻；后续轮在**上一轮 Decode 完成 + 思考
  间隔**后到达。会话内串行、会话间并行；
- 每轮派生量：历史 token 数 h_hist = 上轮最终上下文；预填充上下文 h_pre =
  h_hist + 本轮输入长度；最终上下文 h_fin = h_pre + 生成长度；
- 预填充按 **p_chunk**（参数）分块推进。

## 3. 请求实例映射策略

### 3.1 静态角色分配（离线一次性）

运行前完成两项决策，运行期间**永不改变**：

1. **P/D 角色分配**：n_D 个实例为 Decode、n_P 个实例为 Prefill（n_P + n_D = m）。
   布局遵循**向心约束**：所有 Decode 实例的中心到晶圆中心的距离，不大于任何
   Prefill 实例的中心距离——即"D 居中、P 环绕"，使每个 Prefill 实例的近邻中
   总有 Decode 实例。
2. **P→D 路由规划**：在实例邻接图上为每个 Prefill 实例确定**唯一** Decode 目的地，
   目标为字典序最小化：
   1. 全部路由的总跳数最小（每个 P 连到跳数最近的 D）；
   2. 其次最小化路由间共享链路的重复次数（避免流量热点）；
   3. 最后以确定性顺序破除平局，保证规划结果可复现。

### 3.2 在线映射（Prefill 选择）

新请求到达时，唯一的在线决策是**进入哪个 Prefill 实例**：

- **选择键**：（该实例当前排队的请求数， 实例编号），取字典序最小；
- **平局规则**：排队请求数相同选实例编号最小；
- 实例内部为**严格 FCFS** 队列，同一时刻只服务队首请求的一个 p_chunk 块；
- 队首请求若因 KV 容量不足无法准入，**阻塞整条队列**（队头阻塞），等待容量释放，
  不改投其他实例。

该指标计**请求数**而非 token 数、剩余服务时间或 Decode 压力——排一个长请求与排
一个短请求的实例在此指标下等价。

### 3.3 Decode 归属与批处理

- **Decode 归属**：由静态路由唯一确定——请求进入哪个 Prefill 实例，其 Decode
  实例在到达时刻即已确定，不随任何运行时状态改变；
- **连续批处理**：Decode 实例每轮迭代为**全部活跃请求**各生成 1 个 token；迭代
  时长按（批大小 = 活跃请求数，上下文 = 批内最长上下文）评估；新完成预填充的请求
  动态加入批，生成完毕的请求动态退出；
- **阶段交接**：Prefill 与 Decode 不同实例时，发生一次**整份 KV 的 P→D 迁移**。

## 4. KV 冷热管理策略

### 4.1 两态模型

| 状态 | 含义 |
| --- | --- |
| 驻留（RESIDENT） | 整份 KV 驻留在**某一个** TP 实例的本地 HBM |
| 已删除（EVICTED） | KV 已删除，仅保留逻辑上下文长度，可重算恢复 |

无远端内存层、无按层切分的部分驻留态、无容量驱动的重映射。

### 4.2 历史复用决策（新请求选定 Prefill 实例后）

按会话状态四选一：

1. **无历史**：新会话首轮，直接开始预填充；
2. **本地命中**：KV 恰在选定实例——零开销复用，历史完全免算；
3. **跨片迁移**：KV 在其他实例——整份 KV 按相对 TP 编号一一配对，经片上网络迁至
   目标实例（目标端先落位、源端后释放），走确定性维度序（如 XY）最短路由；
4. **重算**：KV 已被删除——目标实例腾出空间后，全部历史 token 作为额外预填充块
   从头重算（重算块优先于本轮输入块执行）。

### 4.3 淘汰规则（近似 LRU）

实例内某 NPU 空间不足时（准入、KV 增长或水位恢复触发）：

- **候选**：本实例上"已完成且当前不活跃"的驻留会话；活跃会话永不被逐出，触发
  需求的请求自身亦被保护；
- **淘汰顺序**：按 **（最后完成时刻， 会话标识）** 升序——最早完成者先删，
  同时刻平局按会话标识字典序；
- **逐 NPU 收敛**：反复淘汰队首并重查，直到**实例内每个 NPU 同时满足**需求
  （分片按注意力头不均分布，只看总量会误判）；
- **无可淘汰者**：请求等待，绝不改变既定映射。

### 4.4 水位与预留

- **Decode 空间预留**：请求在 Prefill 准入时，即为其静态 Decode 目的地预留
  h_fin 对应的全部 KV 空间，保证 Decode 阶段不会中途断供；迁移完成后释放预留；
- **KV 保留水位**（参数 R_kv）：每个实例被要求始终为"R_kv 个 token 的完整 KV"
  保留空闲空间（逐 NPU 检查）。每次请求完成后立即恢复该水位，必要时级联淘汰
  其他冷会话；所有会话均活跃而无法恢复时记录延迟事件并继续，不死锁。

### 4.5 准入条件（统一公式）

对候选实例 i 的每个 NPU q：

> 剩余空间 F_(i,q) + 可回收空间 R_(i,q) ≥ 本请求还需增加的 KV 分片

其中可回收空间 = 该实例上可淘汰会话的驻留分片之和。**任一 NPU 不满足即整体不可
行**——请求等待而非重映射。

## 5. 算法—体系结构映射分析

1. **向心 P/D 布局 ↔ 固定短路由**：Decode 居中、Prefill 环绕，使每个 P 的最近 D
   都在邻接位置，P→D 交接只需一跳链路；离线规划同时最小化总跳数与共享链路数。
   这是"用物理布局换在线决策复杂度"的典型做法——在线调度器完全不需要理解网络
   拓扑与拥塞。
2. **删除-重算 ↔ 无内存扩展的容量边界**：没有远端内存时，容量压力只能靠删除冷
   会话释放；被删会话回归的代价是整段历史重算，预填充块数随历史长度线性增长。
   该基线把"KV 压力"完全转化为"计算压力"。
3. **队列深度均衡 ↔ 低决策开销**：请求数均衡只需一次取最小值，但与 token 级负载
   脱钩——长请求与短请求同权，实例间实际忙闲可能严重失衡。这是 FACE 引入负载
   感知的直接动因。

**核心局限**（与后续版本的对照点）：映射目标不含任何 KV 信息——历史 KV 的驻留
位置、迁移的网络代价、淘汰后的重算代价都不进入决策。会话下一轮完全可能被派往
没有其历史的实例，触发不必要的整份迁移或重算。

## 6. 仿真视角

- **双层架构**：策略决策由规划器（软件）给出；物理时间由离散事件引擎裁决。两者
  可离线运行（规划器自持逻辑时钟），也可在线闭环（引擎时钟为权威，决策边界为
  到达/预填充完成/解码完成/请求完成，经桥接协议交换"状态增量 → 计算通信图"）。
- **时间模型（Roofline 结构）**：一次混合迭代的时长
  T = T_linear + max(T_prefill_attn, T_decode_attn)，
  其中每项均为"计算界时间（算子量 / 聚合算力）"与"访存界时间（λ_HBM + 字节量 /
  聚合带宽）"的较大者；聚合算力/带宽 = 实例内 NPU 数 × 单 NPU 规格。查找表按
  （批大小、上下文长度）索引，上下文按二次幂分箱取最近箱以控制表规模。计时只用于
  推进事件，不反馈进映射决策。
- **物理建模**：计算节点按 Roofline 与逐 NPU 的 HBM 流体争用模型计时（并发用户
  均分带宽）；跨实例 KV 迁移与控制消息走拥塞感知网络（逐跳时延累加、确定性维度序
  路由）；同一 NPU 上计算串行，跨 NPU 由通信依赖同步。
- **负载输入**：会话化请求队列（会话标识、轮次、输入/生成长度、到达时刻、轮间隔）。
- **可观测指标**：逐请求的 P/D 实例归属与起止时刻、KV 事件流（命中/迁移/删除/
  重算的次数与字节）、逐 NPU HBM 水位、端到端时延分布与吞吐、决策摘要。

## 7. 策略小结

| 维度 | 做法 |
| --- | --- |
| P/D 组织 | 物理静态分区：n_P 个 Prefill 实例环绕、n_D 个 Decode 实例居中 |
| P→D 路由 | 离线一次性规划（总跳数 → 共享链路 → 确定性破平），运行期固定 |
| 在线映射 | Prefill 按（排队请求数， 实例编号）均衡；Decode 由路由唯一确定 |
| KV 层次 | 片上驻留 / 删除重算，两态 |
| 淘汰 | 近似 LRU：（最后完成时刻， 会话标识），逐 NPU 收敛，活跃保护 |
| 水位 | Decode 目的地预留 h_fin 空间 + R_kv token 保留水位 |
| 容量不足 | 队头阻塞等待，不改映射 |
| 历史感知 | 无 |

一句话概括：**用离线的物理分区与固定路由换取在线决策的极简性，以删除-重算为唯一
的容量压力出口，是五版本中最"静态"的参照基线。**
